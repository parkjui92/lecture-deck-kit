# 실제 왕복 기록 — 피드백 3건

`deck.html`(표준 골격 7장)에 화면에서 남긴 지시 3건과 그 결과다.
`queue.jsonl` 이 서버가 받은 원본이고, 아래는 그것이 어떻게 반영됐는지의 전후 대조다.

**관전 포인트는 결과물이 아니라 "무엇이 전달됐는가"다.** 사용자는 슬라이드 번호를 세지 않았고
문단을 말로 설명하지 않았다. 문장을 긁고 원하는 바만 적었다.

---

## 1. 문장 선택 — 표 셀에 예시 붙이기

**한 일**: 5번 슬라이드의 표에서 `무엇을 했는가` 셀을 드래그 → "이 칸 표현이 너무 딱딱해요. 실제 사례를 한 줄 덧붙여주세요"

**서버가 받은 것** (`queue.jsonl` 1행 발췌):

```json
{ "scope": "selection", "sid": "s05", "index": 5,
  "titleExcerpt": "대비가 이해를 만든다",
  "selectedText": "무엇을 했는가",
  "contextBefore": "대비가 이해를 만든다 구분기존 방식제안 방식 관점",
  "contextAfter": "무엇이 바뀌었는가 근거사례 중심지표 + 사례 …",
  "elemHint": { "kind": "표 셀", "kindIndex": 2, "textExcerpt": "무엇을 했는가" },
  "quickActions": ["예시 추가"],
  "instruction": "이 칸 표현이 너무 딱딱해요. 실제 사례를 한 줄 덧붙여주세요" }
```

`selectedText` 가 짧고 흔한 문구여도 `contextBefore/After` 와 `elemHint`("2번째 표 셀") 덕분에
소스에서 위치가 특정된다. **번호가 아니라 내용으로 찾는다**는 것이 이 페이로드의 요점이다.

**전 → 후**

```diff
- <tr><td class="em">관점</td><td>무엇을 했는가</td><td>무엇이 바뀌었는가</td></tr>
+ <tr><td class="em">관점</td>
+   <td>무엇을 했는가<span class="eg">예: "상담 창구를 3곳 늘렸다"</span></td>
+   <td>무엇이 바뀌었는가<span class="eg">예: "대기 시간이 12일 → 4일"</span></td></tr>
```

지시는 한 칸에 대한 것이었지만 대비형 표의 두 열이 짝을 이루므로 반대편 칸에도 같은 형식을 넣었다.
(스타일 규칙 `td .eg` 도 함께 추가됐다.)

---

## 2. 문장 선택 — 추상적인 항목을 행동으로

**한 일**: 7번 슬라이드의 첫 불릿을 드래그 → "이 항목이 너무 추상적이에요. 구체적인 행동 하나로 바꿔주세요"

**전 → 후**

```diff
- <li>첫째, 청중이 내일 바로 쓸 수 있는 것</li>
+ <li>첫째, 내일 회의에서 이 체크리스트 한 장을 꺼내 쓴다
+     <span class="note">추상적인 다짐 대신 당장 할 수 있는 행동 하나</span></li>
```

---

## 3. 장 전체 — "너무 방어적이야"

**한 일**: 4번 슬라이드 위 `💬` 배지 클릭(문장 선택 없이) → "이 장이 너무 방어적이에요. 단정적으로 바꿔주세요"

`scope: "slide"` 로 전달되어 슬라이드 전체가 대상이 됐다.

**전 → 후**

```diff
- <h2>한 장에 메시지는 하나</h2>
- <p class="lead">헤드 메시지를 여기에 한 문장으로 단언한다. 나머지는 전부 이 문장의 근거다.</p>
+ <h2>한 장에 메시지는 하나뿐이다</h2>
+ <p class="lead">제목이 곧 주장이다. 아래 셋은 그 주장의 근거이며, 다른 역할은 맡지 않는다.</p>
```

제목을 명사형(`…하나`)에서 단정형(`…하나뿐이다`)으로 바꾸고, 리드에서 "여기에", "전부" 같은
설명조·완충 표현을 걷어냈다.

---

## 함께 확인한 것

이 3건을 처리하면서 다음도 실측했다.

- **반영 도중 도착한 피드백**: 1번을 반영하는 중에 다른 피드백을 보내 큐에 넣었고,
  커서가 알려준 지점까지만 전진해 **다음 배치에서 정상 처리**됐다(유실 0).
- **자동 갱신·위치 유지**: 세 번 모두 수동 새로고침 없이 화면이 갱신됐고, 보던 슬라이드에 머물렀다.
- **키 격리**: 지시 입력창에 `o`·`n`·방향키를 쳐도 뒤의 덱이 반응하지 않았다.
- **산출물 클린**: 반영 후에도 `deck.html` 에 편집 오버레이 흔적은 0건.

---

※ 이 덱은 **합성 플레이스홀더**다. 실제 강의 내용이 아니라 골격의 각 슬라이드 유형을 보여주기 위한
예시이며, 표의 수치도 의미 없는 자리표시자다. 왕복 기록만이 실제다.
