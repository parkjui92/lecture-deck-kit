# examples — 라이브 편집 왕복 기록

완성된 덱이 아니라 **화면에서 남긴 지시가 어떻게 전달되고 반영됐는지**가 관전 포인트다.

| 폴더 | 무엇 | 봐야 할 것 |
|---|---|---|
| [live-edit-demo/](live-edit-demo/) | 표준 골격 7장 덱 + 피드백 3건 왕복 | 서버가 받은 페이로드에 **무엇이 담기는가** — 선택 문장·앞뒤 문맥·요소 힌트 |

## 읽는 순서

1. **`live-edit-demo/feedback-trail.md`** — 세 번의 왕복을 전후 diff로. 여기부터 본다.
2. **`live-edit-demo/queue.jsonl`** — 서버가 받은 원본 그대로. 사람이 읽으라고 만든 형식이 아니라
   Claude가 위치를 찾는 데 쓰는 데이터다. 번호가 아니라 내용으로 지목한다는 설계가 여기 드러난다.
3. **`live-edit-demo/deck.html`** — 3건이 반영된 결과. 표준 골격의 슬라이드 유형
   (표지·목차·간지·통계·대비형 표·흐름도·마무리)을 겸한다. 브라우저로 바로 열린다.

## 직접 해보려면

```
이 예제 덱으로 라이브 편집 시작해줘
```

`examples/live-edit-demo/deck.html` 을 작업 폴더에 복사하고 서버를 띄운 뒤 브라우저에 표시한다.
문장을 드래그해 아무 지시나 남겨보면 된다.

---

※ 덱 내용은 **합성 플레이스홀더**다. 실제 강의 자료나 수탁 산출물은 포함하지 않는다.
수치는 의미 없는 자리표시자이며, 왕복 기록만이 실제 실행 결과다. 이 정직성 규율 자체가 킷의 일부다.
