# 라이브 편집 문제 진단

증상 → 원인 → 조치 순으로 본다. 대부분은 서버·포트·큐 셋 중 하나다.

## 화면에 편집 UI(우하단 상태 필)가 안 보인다

1. **서버를 거치지 않고 열었다** — 가장 흔한 원인. 파일을 더블클릭해 `file://` 로 열면
   오버레이가 주입되지 않는다(의도된 동작 — 그래서 산출물이 클린하다).
   반드시 `http://localhost:<포트>/deck.html` 로 연다.
2. `?clean=1` 이 URL에 붙어 있다 → 빼고 다시 연다.
3. 주입 여부 확인: `curl -s http://127.0.0.1:<포트>/deck.html | grep -c __editor` → `1` 이어야 한다.
4. HTML에 `</body>` 가 없다 → 말미에 붙지만 스크립트가 늦게 뜰 수 있다. `</body>` 를 넣는다.

## 서버가 안 뜬다 / 포트 충돌

`[오류] 포트 NNNN 를 이미 다른 프로세스가 쓰고 있습니다` 가 나오면:

```bash
lsof -nP -iTCP:4601 -sTCP:LISTEN          # 누가 쓰는지
```
- 이 강의의 서버가 이미 떠 있는 것이면 **그대로 쓴다**(`preview_start` 가 재사용한다).
- 다른 프로그램이면 `.claude/launch.json` 의 포트를 바꾼다(4602, 4603 …).
- 서버는 일부러 다른 포트로 도망가지 않는다. launch.json 의 포트가 단일 진실이어야
  Browser pane 이 늘 같은 주소를 본다.

## 피드백을 보냈는데 알림이 안 온다

큐에는 들어갔는지부터 본다 — **들어갔다면 아무것도 잃지 않은 상태다.**

```bash
python3 ~/.claude/tools/lecture-live-edit/lle.py status --root <폴더>
```
- `pending` 이 올라가 있다 → Monitor 만 죽은 것. 드레인부터 하고 Monitor 를 재장전한다.
- `pending` 이 0이고 `queued` 도 그대로 → 전송 자체가 실패. 오버레이 상태 필이
  "서버 연결 끊김" 인지 확인(서버 재기동 필요). 사용자의 입력은 브라우저에 임시 보관돼 있다.

Monitor 는 세션이 끝나면 사라진다. 새 세션에서는 반드시 재장전한다.

## 자동 새로고침이 안 된다 / 계속 새로고침된다

- **안 된다**: `done` 을 안 했다. 게시 토큰이 안 올라가면 화면은 그대로다.
  `curl -s http://127.0.0.1:<포트>/__status` 의 `version` 이 바뀌는지 본다.
- **계속 된다**: `done` 을 편집 도중 여러 번 실행했다. 마지막에 한 번만 실행한다.
- 지시 입력창이 열려 있는 동안에는 새로고침이 **유예**된다("반영 완료 — 창을 닫으면 갱신됩니다").
  정상 동작이다.

## 문장을 드래그해 선택하면 슬라이드가 앞뒤로 튄다

macOS 트랙패드의 **두 손가락 가로 스와이프가 브라우저 뒤로/앞으로 가기**로 먹히는 것이 원인이다.
문장을 긁을 때 가로 성분이 조금만 섞여도 발동한다. 히스토리에 슬라이드 해시가 쌓여 있으면
뒤로가기 한 번이 곧 "다른 슬라이드로 점프"가 된다.

v0.9.1에서 양쪽을 막았다.
- 덱과 오버레이 모두 `html, body { overscroll-behavior-x: none }` 을 건다 → 스와이프 제스처 자체가 무효.
- 자동 새로고침 시 `location.hash = …` 대신 `history.replaceState` 를 쓴다 → 히스토리가 쌓이지 않는다.

여전히 튄다면 확인할 것:

```js
getComputedStyle(document.documentElement).overscrollBehaviorX   // 'none' 이어야 한다
```

`none` 이 아니면 오래된 덱이다. 덱 CSS의 `html,body` 규칙에 `overscroll-behavior-x:none` 을 추가한다
(서버를 거쳐 열었다면 오버레이가 이미 걸어 주므로, 파일을 직접 연 경우에만 문제가 된다).

## 새로고침 후 다른 슬라이드로 튄다

- 표준 골격은 `#sid` 해시로 복원하므로 정확하다.
- 기존 덱은 방향키 이벤트를 흘려보내 복원한다. 덱이 `keydown` 을 `document`/`window` 가 아닌
  특이한 대상에서 듣거나, 애니메이션이 길면 어긋날 수 있다. 치명적이지 않으니 넘어간다.
- 방금 편집으로 그 `sid` 가 사라졌다면(장 삭제) 같은 번호 위치로 떨어진다. 정상이다.

## 엉뚱한 슬라이드가 고쳐졌다

가장 심각한 실패. 원인은 대체로 **입양 없이 순번(index)에 의존**했기 때문이다.

1. `lle.py revert --root <폴더>` 로 즉시 되돌린다.
2. `lle.py adopt` 로 `data-sid` 를 부여한다.
3. 앞으로 반영 전 `titleExcerpt` 대조를 반드시 거친다. 어긋나면 `--needs-input`.

## 한글 파일명 이미지가 404

macOS 의 NFC/NFD 정규화 불일치다. 서버가 자동 재시도하지만 실패하면:
- 파일명을 ASCII 로 바꾼다(`그림1.png` → `fig1.png`). 시스템이 만드는 파일명은 원래 전부 ASCII다.

## 큐가 이상하다 (커서가 앞서 있다 등)

`cursor` 가 `queued` 보다 크면 손으로 만졌을 가능성이 높다.

```bash
python3 -c "print(sum(1 for _ in open('<폴더>/feedback/queue.jsonl')))"   # 실제 줄 수
```
커서를 그 값 이하로 맞춘다(`lle.py done --cursor <값>`). 큐 파일 자체는 절대 편집하지 않는다.
`applied.jsonl` 은 기록용이라 지워도 동작에는 지장이 없다(보류 건수 표시만 초기화된다).

## 서버 로그 보기

`preview_logs({serverId})` 로 본다. 피드백 1건마다 `[feedback] sNN | 지시 앞부분 | queued=n`
한 줄이 남는다. 상태 폴링(`/__status`)은 로그에서 제외돼 있다.
